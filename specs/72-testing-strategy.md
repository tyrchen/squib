# 72 · Testing Strategy — pyramid, fixtures, compat suite, CI matrix

Status: draft · Owner: workspace · Depends on: [21-api-compat-matrix.md](./21-api-compat-matrix.md), [71-performance-budgets.md](./71-performance-budgets.md)

## 1. Purpose

Pin the test pyramid, the compat suite shape, and the CI matrix. Per [00-prd.md § 10 NFR2](./00-prd.md#10-non-functional-requirements): real integration tests against a real HVF; no mocked vCPU runs in the compat suite.

## 2. Pyramid

### 2.1 Unit tests

`#[cfg(test)] mod tests` per file. Per CLAUDE.md § Testing:

- `rstest` for parameterized cases.
- `proptest` for invariants on JSON schemas, ESR_EL2 decoder, PSCI dispatch, page-bitmap drain.
- `mockall` only where a real dependency is genuinely too slow to spin up; never for HVF.

Coverage target: every public function in `squib-core`, `squib-arch`, `squib-fdt`, `squib-loader`, `squib-mmds` has at least one happy-path test and at least one error-path test.

### 2.2 Integration tests

`tests/` per crate:

- `crates/api/tests/` — drive the API server over a UDS, assert wire shapes.
- `crates/snapshot/tests/` — round-trip save / restore against a real `MicrovmState`.
- `crates/virtio/tests/` — per-device functional tests against synthetic guests.
- `apps/squib/tests/` — top-level binary tests via `assert_cmd`, exercising CLI flags and config-file replay.

### 2.3 Compat suite

Top-level `tests/firecracker-compat/`. See § 3 below.

### 2.4 Snapshot golden tests

`tests/fixtures/snapshots/` holds bitcode-encoded `MicrovmState` blobs from prior runs. Tests assert:

- A round-trip encode → decode → re-encode is byte-equal.
- An older squib release's blob still loads against the current squib (within the same major).

### 2.5 Performance tests

See [71-performance-budgets.md § 7](./71-performance-budgets.md#7-bench-harness). criterion benches are gating in CI per [71-performance-budgets.md § 8](./71-performance-budgets.md#8-ci-gates).

## 3. Compat suite

`tests/firecracker-compat/` is the contract test against upstream Firecracker. Construction:

1. Recorded HTTP transcripts from upstream Firecracker's `tests/integration_tests/` are vendored into `tests/firecracker-compat/transcripts/`. Each transcript is a sequence of (request, expected response) pairs.
2. The harness boots squib, connects to its UDS, replays each transcript, and asserts status code + body match.
3. Each transcript becomes one `#[test]`; failures are diff-friendly.

Per-deviation tests live alongside, asserting the documented behaviour for P / A / R rows in [21-api-compat-matrix.md](./21-api-compat-matrix.md):

- **F rows**: pass-through replay of upstream test cases (suitably aarch64-adjusted).
- **P rows**: a squib-specific test asserts the documented deviation (e.g. `host_dev_name` mapping to vmnet handle).
- **A rows**: a test asserts the field is accepted, the warning is emitted, and the VM otherwise boots.
- **R rows**: a test asserts a 400 response with the documented `fault_message` substring.

The compat suite is **gating** CI (per [00-prd.md § R1](./00-prd.md#8-hard-requirements-10)).

## 4. Test fixtures

| Fixture | Used by | Provenance |
|---------|---------|------------|
| `tests/fixtures/kernels/aarch64-tiny/Image` | boot tests, compat suite | Bundled aarch64 vmlinux + busybox initrd, signed-as-source for SBOM compliance |
| `tests/fixtures/snapshots/v1.0.0/*.snap` | snapshot golden tests | Generated by squib 1.0; refreshed when format version bumps |
| `tests/fixtures/transcripts/*.json` | compat suite | Recorded against upstream Firecracker 1.16; refreshed on upstream pin bump |
| `tests/fixtures/configs/*.json` | static-config replay tests | Hand-authored; covers each endpoint's validation cases |

Bundled kernels are licensed-vetted GPL-2.0 (kernel) and GPL-2.0-or-later (busybox); tracked in `NOTICE` and excluded from the binary build.

## 5. Upstream tracking

Per [00-prd.md § 13 Risks](./00-prd.md#13-risks) and the impl plan:

- Pin to Firecracker minor version (currently 1.16).
- Each release cycle:
  1. Diff `firecracker.yaml` against the last pin.
  2. File issues for new endpoints / fields.
  3. Run the compat suite against the new pin's recorded transcripts.

A schema-diff CI job runs on a nightly cron; it fetches the upstream `firecracker.yaml` and compares against squib's OpenAPI document. New upstream fields fail the job (force a deliberate squib decision per [21-api-compat-matrix.md](./21-api-compat-matrix.md)).

## 6. CI matrix

| Lane | macOS | Hardware | Purpose |
|------|-------|----------|---------|
| `mac-15-arm` | 15 Sequoia | M2 Pro (GitHub-hosted) | Unit + integration + compat + bench (P-axes) |
| `mac-26-arm` | 26 Tahoe | M3 (GitHub-hosted) | Same as above; catches HVF behavioral skew |
| `lint-only` | latest | x86_64-linux (free runner) | `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo deny check`, `cargo audit`, doc build (no HVF needed) |

Per [00-prd.md § 10 NFR2](./00-prd.md#10-non-functional-requirements): both macOS lanes run the full test suite; HVF skew is caught.

## 7. Test discipline

- **No mocked vCPU runs in the compat suite.** A `MockHypervisor` exists for unit tests of higher-level code; it never participates in compat tests.
- **Deterministic seeds.** RNG-using tests (proptest, virtio-rng device) seed from a fixed value; flakes get a deterministic reproduction.
- **No long-sleep timing.** `tokio::time::pause` for synthetic time; never `thread::sleep` in tests.
- **Per CLAUDE.md § Testing**: descriptive `test_should_*` names; `#[ignore]` for slow tests, run with `cargo test -- --ignored` in CI.

## 8. Documentation tests

Per CLAUDE.md § Documentation: doc comments on public items include compileable examples; `cargo test --doc` runs in CI. Examples that require HVF are gated behind `#[cfg(target_os = "macos")]` so the lint-only lane does not need to skip them.

## 9. Invariants

| # | Invariant | Pinned by |
|---|-----------|-----------|
| I-TEST-1 | The compat suite is gating CI; a single failing F / P / A / R row blocks merge. | CI required-checks config |
| I-TEST-2 | Both macOS lanes run the full suite. | CI matrix config |
| I-TEST-3 | No `unsafe` in any test code; tests link the safe wrapper, not the FFI. | `#![forbid(unsafe_code)]` in test crates |
| I-TEST-4 | Snapshot golden tests fail when the format version is bumped without updating the fixture. | CI assertion |
| I-TEST-5 | Upstream `firecracker.yaml` schema diff runs nightly; new fields fail the job. | Cron CI lane |
